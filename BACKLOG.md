# Бэклог

## Быстрые вещи (без нативного приложения, в рамках PWA)

- [ ] **Ярлыки на иконке приложения** (`shortcuts` в манифесте): долгое нажатие на иконку →
  «Новое событие», «Сколько до зарплаты». Не забыть продублировать их в манифесте, который
  `js/boot.js` собирает в data-URL.
- [ ] **«Добавить в календарь телефона» у события**: ссылка на Google Календарь с заполненным
  событием и/или скачивание `.ics`. Разовый перенос, без синхронизации.
- [ ] **Wake Lock в полноэкранном режиме**: экран не гаснет, календарь работает как
  настольные часы. Отключать при выходе из полного экрана.
- [ ] **Уведомления-напоминания, пока приложение открыто** (Notification API). Напоминания
  в точное время при закрытом приложении в PWA без push-сервера невозможны — см. ниже.
- [ ] (под вопросом) Цифра на иконке (Badging API), например дни до зарплаты. На Android
  обычно показывается только точка — проверить, стоит ли.

## Нативная обёртка для Android (Capacitor → APK)

Тот же веб-код внутри Android-приложения; APK собирается в GitHub Actions и ставится по
ссылке, без Google Play. Веб-часть обновляется сама, нативную — переустановкой APK.

- [ ] **Виджет на главном экране**: «до зарплаты N дней», ближайшие события. Нативная вёрстка
  (Kotlin, `AppWidgetProvider`); данные передаются из веб-части.
- [ ] **Доступ к календарю телефона**: чтение событий для отсчётов и запись своих событий
  (системный провайдер календаря, запрос разрешения).
- [ ] **Локальные уведомления в точное время** без сервера.

PWA этого не умеет: веб-API к календарю устройства нет, виджеты для PWA работают только
в Windows 11 (Edge), Chrome на Android их не поддерживает.

## Синхронизация между устройствами без бэкенда (следующая большая задача)

- [ ] Зашифрованный файл в отдельном приватном GitHub-репозитории (`good-calendar-data`,
  `calendar.enc`). Браузер ходит в GitHub Contents API напрямую; fine-grained токен только на
  этот репо (Contents: Read and write). Не в репо сайта — чтобы токен не давал менять код.
- [ ] Шифрование на клиенте: WebCrypto AES-256-GCM, случайный ключ с первого устройства,
  на сервер не уходит.
- [ ] Подключение устройства: QR/ссылка с ключом и токеном в хэше URL (как «Поделиться»).
  На iPhone ссылку открывать в установленном приложении или вставлять в настройки.
- [ ] Цикл: при открытии, возвращении во вкладку, через ~2 с после изменения и раз в несколько
  минут. GET (sha) → расшифровать → слить → если изменилось, зашифровать и PUT с sha;
  на 409/422 — заново.
- [ ] Доделать слияние: время изменения и «надгробия» для вручную изменённых дней
  (сейчас сброс дня не доезжает) и для настроек (сейчас берутся целиком из входящих).
- От пользователя понадобится: создать репо и передать токен через secret-drop.
- Альтернативы: Google Drive appDataFolder (вход через Google), Nostr-реле, jsonbin и т. п.
